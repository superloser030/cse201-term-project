# 수동 테스트 안내 (보고서 screenshot용)

직접 프로그램을 실행하면서 REQ별로 확인하는 시나리오입니다.
각 시나리오의 **"적절한 이유"**는 보고서 4항("각 screenshot은 테스트가 왜 적절한지 짧게 설명")에 그대로 옮길 수 있습니다.

## 준비
1. 프로젝트 폴더에서 `run.cmd`를 실행합니다(더블클릭 또는 터미널에서 `.\run.cmd`).
   - 처음이면 자동으로 build한 뒤 실행합니다.
2. 첫 질문 `Initial condition file name`에서
   - **[S]** 표시 시나리오: 그냥 **Enter** → `sample_initial_condition.txt`
   - **[R]** 표시 시나리오: `test/data/rich_condition.txt` 입력 (잔액·현금이 많은 테스트용 파일)
3. 시나리오마다 **프로그램을 다시 시작**하면 초기 상태에서 시작합니다(test routine과 같은 방식).
4. 아래 입력 칸의 한 줄 = 한 번 입력 후 Enter. `/`는 snapshot입니다.

### 초기 조건 요약
| 파일 | 계좌 (카드 / 비밀번호 / 잔액) | ATM |
|---|---|---|
| [S] sample | Chris: Kakao `1111-1111-1111` / `1234` / 4,000<br>Andor: IM `2222-2222-2222` / `4321` / 6,000 | 1) 000111 Kakao Single 영어만, 현금 [2,3,1,3]<br>2) 000222 IM Multi 영어/한국어, 현금 [0,0,0,60] |
| [R] rich | Chris: Kakao `1111-1111-1111` / `1234` / 1,000,000<br>Andor: IM `2222-2222-2222` / `4321` / 1,000,000<br>Bora: Shinhan `3333-3333-3333` / `0007` / 1,000,000<br>Chris(2): Kakao `4444-4444-4444` / `1111` / 500 (계좌 100-100-444444) | 1) 000111 Kakao Single 영어만, [20,50,20,100]<br>2) 000222 IM Multi 영어/한국어, [0,0,0,60]<br>3) 000333 Shinhan Multi 영어/한국어, [10,10,10,10] |

관리자 카드: `ADMIN-Kakao`, `ADMIN-IM`, `ADMIN-Shinhan` (비밀번호 없음, 그 은행 ATM에서만)

현금 표기 [a,b,c,d] = 50,000원 a장, 10,000원 b장, 5,000원 c장, 1,000원 d장

## M01. Sample Test Case 1 (공식) [S] — REQ4.1, 4.3, 4.5, 10.1
```
(Enter)

1                  ATM 000111
1111-1111-1111
1234
1                  Deposit
1                  Cash
0
0
0
4                  1,000원 4장 (수수료 0원이라 수수료 입력 없음)
4                  End session
/                  ← screenshot ②: 입금 후 snapshot
0
```
- **확인**: Chris 4,000 → 8,000 / ATM 000111 1,000원권 3 → 7장
- **적절한 이유**: 공식 sample test case 그대로이며, 주거래 은행 현금 입금 시 계좌 잔액(REQ4.3)과 ATM 보유 현금(REQ4.5)이 권종별로 함께 반영되는지 확인한다.

## M03. 입력 파일 오류 — 결정 7 (fail-fast)
```
test/data/dup_card.txt      ← screenshot
```
- **확인**: `Duplicate card number: 111111111111` 후 프로그램 종료
- **적절한 이유**: 하이픈만 다른 같은 카드 번호를 중복으로 잡아, 잘못된 초기 데이터로 실행되지 않음을 보여 준다.
